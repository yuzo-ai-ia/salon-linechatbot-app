## 1. この手順書について

### 対象読者

このアプリと同じ構成を1から立ち上げる**構築担当の開発者**。
以下の基本操作ができる前提で書いています（各サービスの一般的な使い方は省略します）。

- Supabase のプロジェクト作成・SQL Editor の操作
- LINE Developers Console でのプロバイダー / チャネル作成
- Vercel へのプロジェクト import・環境変数の設定
- git / GitHub の基本操作

### 完成する状態

- LINE の公式アカウントに問い合わせを送ると、FAQ・メニュー情報をもとに自動で返信する
- 自動で答えられない問い合わせは、オーナーの LINE にプッシュ通知が届く
- `/admin` の管理画面から FAQ・メニュー・お知らせ配信を編集できる
- 本番は Vercel でホスティングし、`main` への push で自動デプロイされる

### 用意するもの

| サービス        | 用途                                    | 必要なもの                     |
| --------------- | --------------------------------------- | ------------------------------ |
| Supabase        | データベース（FAQ・メニュー・会話ログ） | プロジェクト1つ                |
| OpenAI          | 回答文の生成                            | API キー（従量課金の有効化）   |
| LINE Developers | メッセージの送受信                      | Messaging API チャネル1つ      |
| GitHub          | ソース管理・Vercel 連携                 | リポジトリ1つ                  |
| Vercel          | 本番ホスティング                        | プロジェクト1つ（GitHub 連携） |

### 所要時間の目安

各サービスのアカウントが用意できていれば、ローカルで動くまで 1〜1.5 時間、
本番デプロイまで含めて 2〜3 時間程度。

### 関連ドキュメント

- [`README.md`](../README.md) — プロジェクト概要・技術構成・環境変数リファレンス
- [`DEVLOG.md`](../DEVLOG.md) — フェーズ単位の開発記録（設計判断・ハマりどころの詳細）

## 2. 全体像

### 構成

```
                  ┌─────────────────────────────┐
  LINE ユーザー ── │  Vercel（Next.js アプリ）      │
     ▲            │                             │
     │  返信       │  /api/line/webhook  ← 受信    │
     └──────────  │  /admin             ← 管理画面 │
                  └──────┬───────────────┬────────┘
                         │               │
                  ┌──────▼──────┐  ┌─────▼──────┐
                  │  Supabase   │  │  OpenAI    │
                  │ （PostgreSQL）│  │ （回答生成） │
                  └─────────────┘  └────────────┘
```

### 各サービスの役割

| サービス               | 役割                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **Supabase**           | FAQ・メニュー・会話ログ・配信履歴を保存する PostgreSQL。アプリからは Publishable キー（参照のみ）と Secret キー（読み書き）で接続する |
| **OpenAI**             | 問い合わせ文と知識ベース（FAQ・メニュー）から返信文を生成する                                                                         |
| **LINE Messaging API** | ユーザーからのメッセージを webhook で受信し、返信・通知・一斉配信を送る                                                               |
| **Vercel**             | Next.js アプリのホスティング。GitHub の `main` に push すると自動デプロイ                                                             |
| **GitHub**             | ソースコードの管理と Vercel へのデプロイ連携                                                                                          |

### 作業の流れ

1. **Supabase** — プロジェクト作成 → テーブル作成（マイグレーション）→ キー取得（4章）
2. **OpenAI** — API キー取得（5章）
3. **LINE** — チャネル作成 → キー取得 → 応答設定（6章）
4. **ローカルで動作確認** — `.env.local` に値を入れて `npm run dev`（7章）
5. **本番デプロイ** — Vercel に環境変数を設定してデプロイ → LINE の Webhook URL を本番に切替（8章）

いきなり本番に載せず、まず手元（ローカル）で `/` の疎通確認と `try:webhook` を
通してから本番に進むと、問題が起きたときの切り分けが楽です。

## 3. 事前準備

### 3.1 必要なアカウント

2章の表のサービスすべてにサインアップしておきます。OpenAI は**従量課金の支払い方法の
登録**まで済ませてください（未登録だと API がエラーになります）。

### 3.2 ローカル環境

| ツール  | バージョン     | 備考                                                         |
| ------- | -------------- | ------------------------------------------------------------ |
| Node.js | **20.6 以降**  | 確認用スクリプトが `--env-file` を使うため。LTS の最新でも可 |
| npm     | Node.js に同梱 |                                                              |
| git     | 任意の最新版   |                                                              |

### 3.3 リポジトリの取得

このリポジトリを自分の GitHub アカウントに fork（または clone してから新しい
リポジトリに push）し、手元にクローンして依存をインストールします。

```bash
git clone <自分のリポジトリの URL>
cd salon-linechatbot-app
npm install
```

アプリのコードは変更しません。この手順書でやるのは**環境変数と外部サービスの設定だけ**です。

## 4. Supabase のセットアップ

### 4.1 プロジェクト作成

Supabase で新しいプロジェクトを作成します。リージョンは利用者に近い場所
（日本向けなら Tokyo）を選ぶと応答が速くなります。データベースのパスワードは
この手順では直接使いませんが、確実に保管しておいてください。

### 4.2 マイグレーション適用（テーブル作成）

Supabase Studio の **SQL Editor** で、`supabase/migrations/` の SQL ファイルを
**ファイル名の日付順に、1つずつ**貼り付けて実行します。

| 順  | ファイル                                        | 内容                                                                                                                    |
| --- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 1   | `20260903_init_schema.sql`                      | `faq` / `menus` / `conversations` の3テーブル。RLS 有効化・インデックス・テーブルコメント・権限（GRANT / REVOKE）を含む |
| 2   | `20260905_add_needs_human_to_conversations.sql` | `conversations` に `needs_human`（要対応フラグ）カラムを追加                                                            |
| 3   | `20260906_create_broadcasts.sql`                | お知らせ一斉配信の履歴を保存する `broadcasts` テーブル                                                                  |

**なぜ手動なのか**: このリポジトリは Supabase CLI / MCP を使わず、マイグレーションは
Studio で手動実行する運用です。各ファイルの冒頭コメントにも適用方法が書いてあります。

> **補足（権限まわり）**: `20260903_init_schema.sql` には `grant` / `revoke` が
> 明示的に書かれています。これは、Supabase の「新規テーブルへの自動権限付与」が
> Studio 経由のテーブル作成では発火しないことがあり、それが原因で後から
> `42501 permission denied` エラーになるのを防ぐためです。SQL をそのまま
> （一部だけ抜き出さず）実行してください。詳細は `DEVLOG.md` のフェーズ0（続き）。

### 4.3 API 情報の取得

Supabase Studio の **Project Settings → API**（Data API）から次の3つを取得し、
対応する環境変数に入れます（値は次章以降でまとめて `.env.local` に記入するので、
ここでは控えておくだけで OK）。

| Supabase 上の名称                       | 環境変数                               | 種別             | 用途                                              |
| --------------------------------------- | -------------------------------------- | ---------------- | ------------------------------------------------- |
| Project URL                             | `NEXT_PUBLIC_SUPABASE_URL`             | 公開可           | 接続先 URL                                        |
| Publishable key（`sb_publishable_...`） | `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 公開可           | ブラウザからの参照用（RLS で保護）                |
| Secret key（`sb_secret_...`）           | `SUPABASE_SECRET_KEY`                  | **サーバー専用** | サーバー / webhook からの読み書き（RLS バイパス） |

> **キーは新形式（Publishable / Secret）を使います。** 旧形式の anon /
> service_role キーは使いません。`SUPABASE_SECRET_KEY` には絶対に
> `NEXT_PUBLIC_` を付けないでください（ブラウザに漏れます）。

### 4.4 （任意）サンプルデータの投入

動作確認をしやすくするため、架空サロン「hair salon Lin」の FAQ・メニューを
投入できます。SQL Editor で `supabase/seed/sample_data.sql` を実行してください。

- これは**マイグレーションではなく開発用の使い捨てデータ**です（再実行すると
  全削除 → 入れ直し）。
- 本番運用では、このデータを投入せずに管理画面（`/admin`）から実店舗の内容を
  登録するか、`sample_data.sql` の中身を実データに書き換えてから実行します。
- 元ネタの設定は `supabase/seed/salon_info.txt` にあります。

## 5. OpenAI のセットアップ

### 5.1 API キーの発行

OpenAI のダッシュボードで API キー（`sk-...`）を1つ発行し、環境変数
`OPENAI_API_KEY` に入れます（サーバー専用。`NEXT_PUBLIC_` は付けません）。

支払い方法が未登録だとリクエストが `insufficient_quota` などで失敗します。
先に課金設定を済ませ、必要なら**使用量の上限（monthly budget / hard limit）**を
低めに設定しておくと安心です。

### 5.2 モデルの選択

| 環境変数       | 既定値                    | 説明                                                                                     |
| -------------- | ------------------------- | ---------------------------------------------------------------------------------------- |
| `OPENAI_MODEL` | `gpt-4o-mini`（未設定時） | 回答生成に使うモデル。まずは既定のままで十分。回答品質が物足りなければ `gpt-4o` に上げる |

このアプリは、FAQ とメニューをまるごとプロンプトに入れて回答を生成します
（ベクトル検索は使いません）。個人店の FAQ は数十件規模なのでこの方式で足りますが、
モデルを上げるとその分トークン単価が上がる点は把握しておいてください。

### 5.3 動作イメージ

回答生成は「問い合わせ文 → `{ answer, confidence, needsHuman }` の JSON」を返す
処理です（`lib/faq/generate-answer.ts`）。`confidence` が低い・知識ベースに情報が
ない場合は `needsHuman: true` になり、6章で設定するオーナー通知の対象になります。

## 8. 本番デプロイ（Vercel）

> 次回追記予定。GitHub リポジトリ → Vercel Import → 環境変数を Production に登録
> （`NEXT_PUBLIC_*` は最初のデプロイ前に全部／`ADMIN_PASSWORD` は本番専用の別値）
> → デプロイ → `APP_URL` を設定して**再デプロイ**（env 追加だけでは反映されない）
> → LINE Webhook URL を本番に切替 → 実機テスト。

## 9. トラブルシューティング

> 次回追記予定。`JWT issued at future`（`PGRST303`）= 時計のズレ／
> `42501 permission denied` = GRANT 未適用／webhook は 200 なのに返信が来ない／
> 署名検証 401 = Channel secret の取り違え／`NEXT_PUBLIC_*` の変更は再デプロイが必要。
